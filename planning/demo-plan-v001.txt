Yukkuri 乐园：首个本地 Demo 开发与验收草案 v001
日期：2026-10-25（Asia/Shanghai）
依据：requirements-v001.txt 至 requirements-v020.txt。
状态：开发计划草案，尚未实现、测试或交付。以下具体 Demo 内容安排是设计建议，不冒充用户逐项确认。

一、阶段目标
争取在 2026-10-26 至 2026-11-01 提供可在 Windows 本地运行、键鼠操作、简体中文的 Demo。
用户无硬性截止要求；实际范围与可交付日期必须根据引擎准备、物理交互和素材验证结果报告，不能靠缩小最终目标宣布完成。
Demo 要形成可玩循环，验证“经营＋观察＋手动特写互动”是否成立。
不是视频、网页静态模型、纯文字策划或只有调试按钮的系统展示。

二、建议的首轮可玩场景
一个小型乐园和一个可往返的外部观察地区，居民与变化持久保存。
正常开局建议先用少量个体（例如 8—12 只）帮助理解个性与观察；这个数量仅是 Demo 开局建议。
另设典型地区 50 和 100 只的性能验证场景，不以少量 Demo 居民代替原规模目标。
角色以自制临时立体卡通资产或已核查可用资产开始，至少能表现远景辨识与近景表情，不先擅自定案研究待审的物种升级。

三、建议可玩循环
1. 进入小型乐园，切换宏观管理与可见人类主角，移动并选择油库里。
2. 布置基础生活设施，配置食物与简单员工照护任务，资源发生真实变化。
3. 外出观察个体，通过事件积累档案，选择带回并在观察区域安置。
4. 个体自主移动、觅食、休息或互动，少量不同性格与记忆对行为产生可见影响。
5. 对同一个体进入特写，实际拿取/放置、喂食或使用工具，展示接触与力度反馈；不能仅用菜单替代全部物理操作。
6. 退出特写回到原地图镜头，保留状态与物品消耗；员工继续既定照护，主角可再次外出。
7. 手动存档、自动备份、关闭后再启动，恢复相同世界且没有离线时间结算。
先用小目标串联以上循环；不把它写成已经确定的正式第一章剧情。

四、Demo 需要直接验证的规则
经营、观察、互动及人类身份切换，共用真实个体与世界数据。
特写只结算动作，年龄/疾病等被动过程及其他地区暂停；退出不补算停留时间。
普通跨区活动中未访问地区简化模拟，保留个体身份、状态、关系与设施。
真实个性与观察认知分开；至少提供一组观察、判断与后续事件修正的可体验案例。
员工自主完成已配置的日常任务和应急稳定，不擅自执行重大处置。
建造至少验证成套设施放置与基础自定义布置，不以一个预制场景声称整个建造系统完成。
物理互动的接触、移动与力度有一致反馈，界面提供可理解的操作提示。
手动多存档与自动备份能够恢复状态；反复读档不重置已存的救治期限。
关闭游戏后没有离线消耗或收益；自由模式相关开关后续逐项验收。

五、开发顺序建议
阶段 A：选定引擎并验证 Windows 本地运行和导出；制作斜俯视场景、人类移动和角色近景的技术样例。
阶段 B：先验证最不确定的拿取、接触、力度与角色反馈，尽早提供可运行样例供体验。
阶段 C：接入个体需求/行为、观察档案、基础设施与员工，打通最小经营循环。
阶段 D：接入跨区状态、子弹时间与存读档；以真实失败案例检查状态一致性。
阶段 E：进行 50/100 只验证，修复影响操作或持久化的问题，打包本地 Demo 和操作说明。
这是依赖顺序，不是未经评估的逐日工期承诺。持续记录实际进展、障碍和未完成项。

六、保留在完整游戏范围内的后续系统
完整世代、母系遗传、两套变异和三类升级触发、复杂群体关系。
多用途金银铜牌、外部评级、全部三类经济渠道、多个地区及完整章节内容。
完整伤情分类、野外自行处置、救治窗口、昂贵内馅转移及身份沿用风险。
全部动作和工具、伤亡表现配置、各难度与自由模式设置、丰富建筑与物品、最终角色资产及语音。
上述内容可能在 Demo 中以部分案例验证，也可能后续扩展；是否已实现必须逐项报告。
未经用户审阅的具体物种与升级形态不自动入库；未选中项不等于被永久删去。

七、验收与证据
交付应包含实际 Windows 可执行构建、简体中文操作说明、已知问题及未实现清单、相应源工程与版本记录。
实际启动并操作建造/观察/人类移动/特写，完成一次往返与存读档；仅无头测试或编译成功不足以证明可玩。
保存实际性能环境与 50/100 只场景测量结果；目标硬件尚未定，不先承诺帧率。
验证特写后重复结算、跨区重置、离线变化、观察泄露真实词条、员工越权等真实失败场景。
记录用户试玩反馈；模型自评和文件存在不替代用户体验验收。

八、资产与发行边界
每个外部资产记录作者、原页面、许可文本/版本、获取日期、商用与署名要求、修改记录。
不能仅凭搜索标签“免费”推断可商用；自制资产与外部来源分开记录。
付费素材先形成具体候选、价格、许可和用途；当前没有确定的采购清单或金额。
本地 Demo 不等于 Steam 抢先体验；后者需要完整可玩的核心体验、实际商店及构建准备和审核。
不因希望下周看到 Demo 而自动发布商店、支付费用或创建定时自动任务。
