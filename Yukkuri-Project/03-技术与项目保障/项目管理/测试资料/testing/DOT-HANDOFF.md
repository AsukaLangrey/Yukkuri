# 给 dot 的任务说明

当前仓库 https://github.com/AsukaLangrey/Yukkuri 为公开仓库。此次夜间源码交付先读 `testing/night-20261031-first-pass.md`，固定完整提交后按用户授权执行单轮测试。获取本说明或源码包不授权建立、启动或恢复周期任务；已经暂停的任务保持暂停。

以下保留周期测试的接入约定，仅在用户明确授权启用时适用：每小时检查一次 `main` 是否出现需要测试的更新，按同一提交号测试，并把结果提交到同一仓库的 `codex/dot-test-results` 分支。

开始前阅读 `testing/PROTOCOL.md`、`testing/request.json`、`README.md`，以及当前源码提交中的适用指令。先确认你所在的是用户安排的远程测试机器，记录系统、CPU/GPU、驱动、工具链和显示环境。不要在原开发机 `D:\Project\Yukkuri` 启动任何项目程序。本说明不代表远程定时器已经安装。

首次接入需要：仓库读取及结果分支写入权限、Git LFS、可用的测试工具链。凭据只放远程机器的凭据管理中，不提交。当前安装脚本面向 Windows x64；其他系统不得直接声称兼容，也不要静默换引擎版本。缺环境或权限就提交 `blocked` 报告（能写仓库时），不能写仓库则向用户报告。

获准启用周期测试后，在远程机器建立每小时触发的任务，禁止重叠执行。第一次先测试当前 `main`；后续按规范去重。你只提交测试证据，不修改产品代码、不覆盖已有试玩包、不强推。源码修复由开发侧另行处理。

每次测试结束，无论通过、失败、崩溃还是缺条件，都提交独立的 `report.json` 和 `summary.md`，更新 `testing/latest/dot.json`。模板见 `testing/report-template.json`。请把测试提交链接交给用户，开发侧会定期读取结果分支。

效果检查应区分自动规则、真实运行和人眼观察。用户安排远程测试不等于自动授予桌面、窗口读取或截图权限；若你的环境要求单独授权，请只把该部分标为 `blocked`，继续其余已授权检查。不能用静态代码阅读或离线图片代替实际效果验收。
