# 重新开院保持经营模式：修复与验收

## 交付范围

- 独立分支：`alice/20261106-courtyard-restart`。
- 适用基线：`e8d96a78f49182eb17e269e2b62a738c7a9bb7ea`。仅供用户审阅后自行合并，不修改主分支。
- 依据：`05-游戏设计/自由模式-繁育经营闭环.txt` 已确认的新院经营规则。正常开院应开启经营进度，保留初始伴侣关系和设施解锁条件。

## 问题与修复

首次进入场景使用 `CreateCourtyardEconomy()`，但设置中的“重新开一间小院”确认保存后调用旧的 `CreateInteractionPlaytest()`，导致重新开院失去经营进度模式、初始伴侣关系与经营设施解锁限制。

产品改动仅将重新开院的工厂调用统一为 `CreateCourtyardEconomy()`。保存旧世界、取消操作、载入已有存档的逻辑不变。另增加可选的真实场景回归入口与隔离测试夹具，不增加玩法设计。

## 已确认验证

相同最终夹具通过 Godot headless 场景内真实按钮的 Pressed 信号执行设置、取消及重新开始流程：

- 原工厂：19 项中通过 15 项，失败 4 项，退出码 1。失败项为重开后的经营模式、初始伴侣、设施解锁限制，以及重复重开的标准经营起点。
- 修复后：连续 3 次均 19/19，退出码 0。
- 恢复修复源码并重新编译后的最终确认：19/19，退出码 0；已记录实际源码与程序集哈希。
- 暂停和运行状态取消均保持原世界与设置；取消不创建自动存档。
- 确认重开前自动槽保存原世界；手动槽内容逐字节不变。
- 使用真实出售操作建立非零销售进度后，重开清除旧销售进度。
- 初始资源验证包含资金 240、食物 50、供水份数 20、3 只个体；重复重开仍保持标准经营起点。
- 通过注入非法负金额触发 `SaveStore.Validate` 拒绝保存，确认不会重置当前世界或覆盖先前自动与手动存档。
- 缺少隔离 profile 或重复使用已有存档的 profile 均拒绝，退出码 2，不生成结果文件；重复 profile 中既有合成存档哈希不变。

附带 JSON 为最终旧工厂、修复确认与 profile 防护的简洁结果，不含个人存档或本机绝对路径。

## 测试退出处理

验证初版直接退出引擎时，verbose 偶发报告 `AudioStreamWAV` 和 `AudioStreamPlaybackWAV` 各一实例。仅在测试结束时提前停止并解绑音频流，等待 0.2 秒让音频线程处理退出，保持产品音频代码不变。使用相同最终夹具的旧工厂、修复后三次与恢复后确认均未再出现 ObjectDB 泄漏警告。

负金额故障注入仍会按预期产生“世界数据越界”验证警告。这不是无警告运行，也不应据此声称已修复产品音频泄漏。

## 验收边界

- 验证真实场景按钮信号、世界状态和存读档，不代表原生鼠标输入或视觉验收。

- 所有会写入的夹具使用全新独立测试 profile 和合成状态；未读取或修改个人存档。普通存档隔离由路径与入口保护约束，不通过扫描个人存档证明。
- 旧存档载入代码未修改，这是静态审查结论，不声称本次完成旧版个人存档兼容动态测试。
