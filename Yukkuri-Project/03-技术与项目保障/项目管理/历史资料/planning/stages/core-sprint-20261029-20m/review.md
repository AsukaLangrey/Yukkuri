## R1 · P1 · 被托举的个体死亡后，单手占用永久残留，其他个体也无法搬运

**实际界面触发路径**

1. 在默认小院保留“致命后果：开”。通过现有按压工具让一只个体进入重伤状态，随后停止施力。连续小额伤害会先进入 90 秒重伤倒计时，不需要改存档或调用隐藏接口。
2. 使用“抱抱 → 托起来”托住该个体，再松开工具。该工具原本就有“松开后仍托着，使用放稳结束”的语义。也可持续空手托举直到死亡，但工具松开版本不依赖本轮保留的空手松手改动。
3. 回到普通小院时间，不救治，等重伤倒计时结束。不要在近看或暂停状态下等待，因为这两者不推进重伤时间。
4. 尝试放稳死去个体，再选择另外一只活体使用托举。前者被拒绝，后者一直提示手中还有另一只。若另一个个体在悬挂装置上，“解下”同样被占手条件阻止。

**源码依据与调用次序**

- `InteractionWorld.cs:128–132`：死亡对象的全部互动被拒绝；重伤对象明确允许 `Lift`、`PutDown` 等支撑动作，所以第 2 步可以正常发生。

- `SetProcess(false)` 只停 Main 自身普通帧；Wait 使用 SceneTree.CreateTimer，不依赖 Main._Process，所以不会因停帧永远等不到。音乐、音效播放器为独立子节点；本轮未设置全树暂停。Main 的自主求助声和区域重建因此不再混进这次采样。
- 成功经窗口 CloseRequested 进入 QuitGameCleanly，失败进入同一清理方法；其异步退出先置 `_ready=false` 并停音，再等待 .2 秒。StartMilestoneAudio 的 finally 会先移除录音效果、恢复原 IsProcessing，再由 using 释放 capture；恢复 Main 处理不会在退出等待期间重新推进世界，因为 `_ready` 已为 false。
- `_music.Stop()` 之后先测静音基线，再测各一次性声；每个声 1.2 秒的 RMS 和 `!_sfx.Playing` 联合判断，能区分没有发声和误循环。零音量/静音断言阈值与原检查一致，没有放宽。保留的 -80 dB 方式是近似静音，不应描述成播放器停止或绝对零样本。
- 隔离的是自动行为，仍假定检查期间没有外部人工点击 UI；SetProcess 不是禁止所有输入。若远程要验证手动干扰或正在播放时点静音，应按 audio.md 的实际 UI 案例另测，不用这份 M01 检查替代。
