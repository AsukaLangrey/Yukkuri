## S1：显式 null 台词通过校验，实际显示入口随后空引用

触发条件：结构可解析的互动主档里，任一个体 `Speech=null`；例如还有 `ReactionRemaining=4` 的活跃反应。当前程序正常赋值路径均使用字符串，本轮未发现正常游戏自行生成 null 的证据，这是损坏输入边界问题。

依据：`Speech` 的属性默认值是空字符串，但 JSON 的显式 null 会覆盖该值。原 `SaveStore.Validate` 和两个后续验证器均未拒绝它，因此 `Load` 返回主档，不尝试好备份。默认小院 `LoadRoom` 随后替换 Sim、刷新界面；`InteractionRoom.Ui.cs` 的台词显示及 `InteractionRoom.cs` 的声音筛选读取 `c.Speech.Length`。当前显示循环和 `CreatureActor.Refresh` 也存在同样访问。活跃反应不会在下一个表现步立即清成空字符串，因此不是只存在于脱离默认流程的直接 API 调用。

修改：在 SaveStore 的个体基础校验中明确抛 `InvalidDataException`。这个检查同时用于读取主档、检查现有主档、校验待保存状态和临时档，既恢复备份资格，也阻止坏主档被当成有效上一代覆盖好备份。不在界面临时吞掉空引用，不改变序列化格式。

回归源码：复用原结构损坏 helper，检查受控拒绝、回退相同有效备份、拒绝覆盖损坏主档及两个文件原样保留；另检查非法候选不能覆盖有效主档/备份。用 JsonNode 真正移除 Speech 字段的合成案例，要求读回空字符串、且不触发回退，保留缺省兼容。

## S2：主档拒绝访问时跳过了可读备份

触发条件：`File.OpenRead(primary)` 抛 `UnauthorizedAccessException`，而对应 `.bak` 仍可读。权限设置或槽位路径被目录占用可导致这一类错误。

依据：原 Load 两层过滤器只接受 IOException、JsonException、InvalidDataException；UnauthorizedAccessException 不在其中，会直接离开 Load。默认 LoadRoom 虽会显示读取失败，但不会尝试已有备份。

修改：仅向主档和备份读取的异常过滤器增加 `UnauthorizedAccessException`。主档失败则尝试备份；两者都失败仍由原有 InvalidDataException 加 AggregateException 保存两次原因。没有扩大为捕获任意程序异常，也没有修改文件、权限或保存覆盖策略。

回归源码：在独立随机临时目录中，以目录占用主档文件路径，并直接放入合成有效备份，要求读取备份且两条路径内容不变；两条路径都为目录时要求受控拒绝且不删除目录。这是文件打开错误分支的合成覆盖，不是已经完成真实 ACL 权限验证。
