# 输入切换与取消：第三轮只读审查

结论：本轮发现两个真实界面路径的问题：自动保存会取消尚在手里的食水；同一种 Drink 外观从直接工具切到实物杯时可保留旧低水位。常规切目标、切工具、弹窗恢复路径未发现新的旧力度继承、重复入口或过期手势恢复问题。

基线：`ee65c8041f4cfd66eb17f533690358798a13e9ec`。阅读时相关产品源码没有未提交差异；工作区另外的 PLAN/STATUS 改动不属于本任务。仅新增本文，没有修改产品或检查源码，没有暂存、提交或推送。未启动任何项目、检查程序、编译、模拟、预览或 computer-use。

## P2：自动保存把“没有喂食手势”误当成“没有拿东西”

**实际触发：**空手按住地上的饭/甜食/水，移到空地，仍按住左键；也可在已经喂过一口后，把剩余容器移离角色。跨过自动保存时间点时，东西会回到原处，手也隐藏，后续继续移动鼠标不再搬着它。不是只在手工构造模拟状态时成立。

证据与顺序：

1. `InteractionRoom.Input.cs:172` 拿起实物只设置 `_heldSupplyId`、`_mouseHeld=true` 等，并调用 HoldSupply；此时没有 BeginInteractionGesture。
2. `InteractionRoom.Input.cs:371–380` 只有到嘴边才建立喂食手势；移开到无目标或另一目标时会先结束旧喂食手势，但保留手持容器。已入口标记 `_supplyBiteTaken` 正确保留。
3. `InteractionRoom.cs:199–201` 自动保存条件只检查 `_autoClock>60`、`!Sim.HasInteractionGesture`、无弹窗、非恢复备份，漏掉 `_mouseHeld`/`_heldSupplyId`。
4. `InteractionRoom.cs:288–292` 的 SaveRoom 无条件先 CancelGesture。
5. `InteractionRoom.Input.cs:252–259` 因而 ReleaseSupply、清 `_heldSupplyId`、清 `_mouseHeld`、隐藏手；`InteractionSupply.cs:22–35` 不给落点时恢复原地，空容器则移除。

**影响边界：**这是未经用户松开或取消的持有中断，不是已吃份量退款，也不会自动多喂一口。已入口部分仍保留，剩余部分回原地；问题在于后台保存改变了当前操作。时间点若恰逢两只角色之间换目标，更容易误看成目标切换丢了手持物。

**最小建议：**自动保存门禁同时排除游戏侧仍在进行的鼠标操作，至少检查 `!_mouseHeld && _heldSupplyId==null`，继续保留模拟侧手势检查。若提取统一“交互忙碌”判断，再考虑中键观察 `_orbiting`，因为 SaveRoom 的 CancelGesture 也会结束它。不要把显式保存/退出时必要的状态收束一概删除，也不要把手持物直接带入保存来绕开现有保存规则。

**远端验证建议：**在实际小院中分别拿起未喂食容器、喂过一口后仍有剩余的容器，保持左键不松并离开嘴部，跨过自动保存时间点。应保持持有、不新增入口、不补回已吃份量；主动松开后才放下，随后自动保存再发生。不要只调用模拟 Begin/End 代替这个界面门禁案例。

## P2：同名 Drink 工具复用旧网格，实物杯沿用上一口的低水位

**实际触发：**先在地上准备一杯仍有水的实物。选“喝水”直接工具完成一口，等杯内水面降下；右键切回空手，再拿起地上的实物杯。若中间没有展示另一种动作的工具，新杯手中外观仍使用上一直接工具的低水面，直到真正换一种展示工具。

证据与顺序：

1. `InteractionRoom.Input.cs:345–350` 在直接 Drink 手势中按吞咽进度写 `_cupWater.Position` 和 Scale；完成后高度是 `SipWaterHeight(1)=.015`，初始满水高度为 `.056`（`InteractionToolSurface.cs:10–13`）。这里说的是低水位，不能称实际水份量已经变零。
2. DisarmTool/CancelGesture 清输入并隐藏手，但没有重建外观或清 `_shownTool`。
3. 拿起实物水在 `InteractionRoom.Input.cs:172–174` 又设置 `_action=Drink` 并 ShowInteractionTool。
4. `InteractionRoom.Tools.cs:36–39` 仅按 action 缓存；`_shownTool==_action` 就直接返回，保留上一次水面的位置和比例。
5. `InteractionRoom.Input.cs:383–385` 的实物路径只按 `obj.Portions>0` 改 Visible，不恢复水面的高度与比例。地上杯的表现则由 `InteractionRoom.cs:183–187` 按实际来源填充，故同一实物拿起前后可表现不一致。

**影响边界：**现有份量、入口与取消结算仍正确；这是切换来源时旧外观状态泄漏，不是剩余水真的丢失。它会给用户错误的剩余量提示，并且不是只持续一帧。

**最小建议：**实物持有路径在设置水面 Visible 时，也从当前实物状态更新水面高度和比例，按项目已有的实物水杯规则统一处理。不要只按“动作名称未变”假定外观的消费进度也未变；也不必每帧重建整套工具网格。

**远端验证建议：**按上述实际操作连续切换两次，并对照实物杯的真实 Portions、拿起前地面水位、拿起后手中水位。再检查空容器隐藏水面和剩余容器的正常显现。没有实机预览，本文只确认这条赋值链，未声称观察过画面。

## 本轮要求的其余路径：未发现新的具体缺陷

- **按钮选目标/换工具：**Ui 的 SelectOil、SelectGroup、SelectAction 在改变目标或 action 前 CancelGesture（158–159、136–145）。Cancel 先清输入追踪器再结束原模拟手势；模拟 End 按原 TargetId 结算，且先置空手势。多层工具切换重复调用 Cancel 不会重复结算。目标/工具按钮是不可键盘聚焦的普通按钮；正常鼠标点按钮要先松开旧左键操作，不能把纯 API 的“按住左键同时任意改 SelectedId”当成实际入口。
- **仍按住跨过另一只角色：**普通接触不把手势目标改成新命中的角色；`touching` 必须匹配旧 TargetId，不匹配时 ContactMotion 收到 null 并重置、表面 tracker 也断开。新的按下另行初始化两个 tracker。切工具的基础力度来自该工具记忆或默认值，属于明确配置，不是上一手势的速度余量。
- **实物跨目标：**ProcessHeldSupply 先 End 旧喂食，再按需要设置新 SelectedId 并 Begin。未入口时新目标重新等邀请；已经入口则 `_supplyBiteTaken` 阻止同一次按住再喂。该字段只在下一次真正拿起实物时清零，切目标并不会清零。下一次正常身体操作仍走 tracker 初始化。这里没有发现重复扣份或把旧急停传给新目标的路径。
- **右键、暂停、弹窗：**右键 DisarmTool、TogglePause、OpenModal 都先 Cancel；OpenModal 随后才设暂停并显示遮罩。弹窗开着时 `_Process` 不采样互动；CloseModal 只恢复暂停状态和界面，不重新 Begin、不恢复 `_mouseHeld`/持有容器。窗口失焦也调用 Cancel。关闭弹窗后，仍物理按住旧左键不会自己续上已取消动作。
- **入口前/入口后取消：**入口前未扣实物份量；入口后份量已扣、Applied 已锁存，End 只记一次本次经历，不退养分或额外扣份。ReleaseSupply 只放下尚存部分，和自主进食“未入口预留份量”的退款路径是两件事。当前审查没有把二者混为误退款。
