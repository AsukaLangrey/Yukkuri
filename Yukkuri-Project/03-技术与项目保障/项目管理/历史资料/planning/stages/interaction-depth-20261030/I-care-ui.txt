I 家庭照护实际入口与反馈（源码交接，尚未运行）

范围：本代理仅修改 InteractionRoom.Family.cs、I-ui-gap.txt、本文件。FamilyCare 核心由身体代理修改，陌生非亲代自主接纳由社会代理修改；未改其他产品文件。未在原机执行编译、检查、游戏、预览、截图、computer-use、项目脚本或 Git。

已接入的界面行为
- 成人/幼体组合优先展示成人照护幼体这一方向，不把幼体当递送者。
- 两位成人组合分别展示 A 照护 B 与 B 照护 A，每一方向直接读取 Sim.FamilyCareReason，只读说明由同一核心提供，不在 UI 复刻年龄、亲密、食水、伤残阈值。
- 照护入口放在双方摘要后，早于结伴/繁育按钮；短按钮配完整姓名提示，方向文字显示具体双方。
- 目前可以安排的幼体照护说明真实靠近/接食；如果核心允许且照护者不能自行移动，明确只能在贴近的幼体旁保暖，食水仍需要玩家或能移动的家人帮助。
- 成年食水帮助明确不会改血缘或成为养子女。亲代照护者与通过持续照顾建立的非亲代养亲分开描述；血亲母亲/父亲记录仍单独保留，成年人帮助不由 UI 添加 CaregiverIds。
- 从真实 CareTargetId 描述当前照护方向；只有 CareParcelId 对应实物且 CarrierId 匹配、未收纳/未手持时，才写正在搬送一份水/食物。没有包裹时只写已安排且目前未搬送，不凭一段文字冒充已经走到或送达。水不被 UI 宣称一定干净。
- 选收件人时也会查正在照护它的人及当前阻碍；已停止的任务通过核心写入的 Family.LastEvent 展示结果，而非只保留旧接受消息。

照护专用失败处理
- 新增 ApplyFamilyCareCommand，只用于照护按钮。前置原因存在时，直接在原面板显示并保留双方选择；不会统一关面板。
- 若用户打开面板前已暂停，面板说明需关闭并恢复时间。点击不绕过原暂停，不调用实际安排；暂时模态暂停本身不被误报成照护阻碍。
- 原本运行且只读原因允许时，先走原 CloseModal 恢复原时钟，再调用真实 ArrangeCare。以实际 CareTargetId 对上收件人确认接单；若仍失败，重新打开同一组合并展示真实结果。
- 其他相处、繁育、教导、冷藏等按钮仍走原 ApplyFamilyCommand，未扩大其交互范围。没有直接增加营养、关系、照护时长或改暂停。

与核心协作的必要契约
FamilyCareReason 不查 Pause、不改变关系/消息，只返回当前具体原因；已有同一目标照护不应因其自身任务被拒绝。原因应说明下一步，不能仍把饥渴/休息/固定/距离全部合成一句笼统文本。
取消任务应在清 CareTargetId 前记住收件人，把可读中断原因同时写给当事人，避免选宝宝时任务已清除而无从知道谁停止了照护。收尾已静态核对身体代理实现：FamilyCareReason 拆出吃喝、休息、当前相处/指令、未放稳、固定/包裹、关系与接近阻碍；同步取消与照护者失去余力的分支已传入同一核心具体原因，实物被拿走另有说明；取消写双方 LastEvent（死者不覆盖），已有同一照护任务不被误判为忙，成人不会被 RegisterFamilyCare 新写为养子女。

远端观察与检查清单（需独立获授权机器、记录完整源码提交）
1. 幼体/成人两个选择顺序互换：都显示成人照护幼体；两成人时两个方向各有自己的当前原因，不混淆照护者与收件人。
2. 地面 Wrap 幼体：符合新核心条件时可接受照护，界面不要求无条件解开；真实保暖、食水接入由核心验证。
3. 失能亲代已贴近幼体：能请求原地保暖，明确不能搬送；距离不够时说明先搬近，不伪造移动。
4. 成年失能/恢复中的亲近家人：实际调用安排→找到一份食水→搬运→放到可达位置→实际吃喝。界面只按当前阶段描述，不能点击即补营养或新增养亲。
5. 照护者饥渴、休息、同伴占用、收件人未放稳/被固定/视线阻碍：展示具体原因及处理办法；反复失败不关闭面板、不丢双方选择。
6. 运行中中断：从照护者与收件人两侧均能看见原因，当前搬送文案消失；实物不复制、假送达不出现。
7. 用户原本暂停：失败留在面板且不恢复时间；运行时的模态暂停：只读原因能正常显示，真正安排前按原逻辑关闭面板。近看可以先安排，过程回小院才推进。
8. 血亲与养亲记录保持身份连续；陌生非亲代必须经核心真实持续相处/照顾，成人临时帮助不变成收养。

限制：没有本机构建或实机检查。长姓名、滚动长度、按钮可点击区域、动态中断显示与实际搬运时序均待远端观察；静态接线不能替代这些证据。
