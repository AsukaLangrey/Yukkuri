## 实际原因与修复

原先 FeedMeal/FeedSweet/Drink 已接受一口后只更新文字，Care 的 Applied 分支只返回上次反馈，RepairAccessory 完成后只返回“已整理好”。这些手势仍在默认姿态占用分支中；继续按住空工具会一直阻挡自主取食、喝水和休息。

实际游戏顺序是 `ProcessRoomGesture → AdvanceInteractionPresentation → Advance → 选择显示姿态`。因此不能只把“吃完”做成输入帧上的判断：输入返回时还在吃，表现阶段可能已咽完，世界阶段已经尝试走路，最后若仍用旧 `_gesturePose`，就可能带着上一帧的吃饭姿态平移。

此次将两件事分开：

- **动作已经完成后，不再由手势提供身体姿态。** 食水在 Applied、护理在 Applied、修补在 RepairFinished 时归还姿态。最后显示使用当前 `InteractionPresentation.Pose(c)`，保留实际吞咽、护理收尾以及更新的痛感或自主吃喝。
- **这一轮收尾尚未结束时暂缓自主动作。** 新增私有 `CompletedGestureStillSettling`。食水等待实际嘴中一口及现有 `.6` 秒 swallow；护理/修补仅等待与本手势反应序号相符的完成反馈。反馈结束后把本手势的 `CompletionReleased` 锁存为 true，后来的自然吃喝不会重新变成旧手势的收尾。

`CompletionReleased` 只在内存中的 ContactGesture 上，不新增存档字段。食水收尾还排除 GroundIntake，避免曾因装置限制未查询自主判定的旧手势把后来地面进食认作自己的一口。没有自动结束或重新开始手势，不改 `InteractionIntakeAccepted` 的 Applied 判定，不改一口份量、药品消耗或容器持有状态。Hold/Press/Lift/Block 等有意持续操作未改。

修补完成的直接 Feedback 现在登记 `g.ReactionSerial`：马上松手或取消可以按原有规则清掉自己的 accessory-watch；若随后出现新的痛感/自主反应，序号不同，仍不清除。原本完整的饰品在 Begin 就标记为已完成且已释放，不增加 CompletedRepairs、不制造实际修补记录。完成后即使再次受损，同一次按住也不自动重做；需要松开再开始新修补。保留原完成文案中的“戴回”，没有修改旧案例的断言。

## 食水不在嘴边及重新接触的边界

直接食水工具只在有效嘴边邀请时占用动作；贴着身体侧面不构成喂食，也不应拦住自主生活。手持实物路径原来只把嘴部传作有效接触，这次没有修改游戏接线。

释放非嘴部占用后，需要同时防止“返回嘴边覆盖另一口”这个连带问题：手在旁边等待时，角色可能已经自主取食；旧 Continue 没有 Begin 的嘴中有食物检查，重新接触会调用 BeginIntake 覆盖自然进食来源甚至尚未入口的预留。

现在未接受的手喂，在当前一口或 swallow 收尾期间：

- 不取得姿态占用，避免表现阶段因新手势把原地面来源分离/退回。
- Continue 只等待当前一口，清零本手势的邀请驻留时间；不扣手里的份量、不覆盖来源。
- 当前一口及收尾结束后，重新累计完整 `.65` 秒邀请，再接受手里的一口。
- 已经接受过的旧手喂仍优先走 Applied 分支，永不再次入口；后来的自主嘴中一口不会被误报为旧工具新接受了一口。
