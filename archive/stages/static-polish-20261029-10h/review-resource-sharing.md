## 核对到的实际顺序

默认入口 `src/Yukkuri.Game/InteractionRoom.cs:156` 在一帧内依次处理输入、表现推进、普通时间推进，再刷新画面。`TickInteractionWorld` 顺序遍历个体，没有为各只油启动并行消费任务。这里要分析前一只修改状态后后一只看到什么，不能把同一帧两只都想吃描述为线程竞态。

### 两只接近同一来源

- `NaturalLife.cs:271` 的移动个体入口和 `InteractionBehavior.cs:422` 的近旁取食入口，都要求实际来源仍有份数、没有被收起或手持，并要求 `NaturalResources.Consumer` 为空。
- `NaturalLife.cs:351` 的 `BeginNaturalIntake` 在返回前立即扣掉一份有限食水，设置 `NaturalIntakePending` 和来源 ID。这时尚未增加食水值或污染暴露。
- 同一世界步稍后处理的另一只会看到已扣的份数及占用者。最后一份预留后份数已经是零；来源还有余量时也不能与当前来源占用者同时开始这一口。
- `Consumer` 对当前源关联和正在进行的自然进食做检查。上一只已入口后若因其他动作解除源关联，另一只可以开始取剩余的一份；前一只继续咽自己已经吃到的食物。这是两份食物的先后处理，不是同一份被吃两遍。
- `PruneConsumedSupplies` 除了看消费中的来源，还额外保留任何尚未入口的预留引用。即使消费中的个体因死亡等暂时不再被 `Consumer` 找到，仍不会仅因份数为零就删除其尚待处理的来源。

### 入口与污染暴露

- `InteractionBehavior.cs:105` 仅在 `NaturalIntakePending` 为真且达到嘴部接触阶段时调用 `CompleteNaturalIntake`。
- `NaturalLife.cs:363` 再检查实际来源、地区、手持/收起状态、嘴部可达性和支撑高度。条件不成立就分离预留；成立时先把 pending 标记设为 false，再增加食水值并登记一次暴露。
- 之后的表现帧不会再次进入这次 pending 结算。`RegisterNaturalExposure` 只在实际自然入口、或真实手喂接受来源的一次处理中调用，不是在接近或单纯预留时调用。
- 警惕来源的记忆使用近期入口记录，不直接把污染值写成“已经知道有毒”；这里没有发现共享来源导致另一只的暴露被复制给当前个体的路径。

### 拿起、取消、换位置与收起

`InteractionSupply.cs:11` 的 `HoldSupply` 先把物品设为手持，再分离所有关联者：

| 当时状态 | 分离后的处理 |
| --- | --- |
| 预留但未入口 | `DetachNaturalIntake` 把一份还回来源，清 pending、口中计时和来源引用；不登记暴露 |
| 已入口、还没咽完 | 不退份数，保留口中计时，只解除来源引用；不重算食水和暴露 |
| 再次分离同一个体 | pending 已清、来源引用已空，不会再次退款 |

拿起后所有自然取食入口排除 `HeldByHand`。`ReleaseSupply` 的取消路径只放回原位置；有效新落点先检查落点，失败时保持手持，由游戏入口再调用无坐标释放。两个调用不会各自退一次份数，因为退款在最初拿起/分离时已经完成，释放不做退款。

`InteractionBehavior.cs:457` 的收起路径同样先分离关联者，再把实际剩余食物返还有限库存，最后移除物品。未入口的预留已先还给来源；已入口的一口不再算入返还份数。重复收起因对象已不存在或已收起而失败。

从默认鼠标入口移动来源要经过拿起/释放；没有看到绕过分离、直接拖动正在预留的饭或水坐标的路径。把 RoomObject 在外部直接删除、换种类、换 ID 或凭空改份数，不能当作默认小院可达的重复退款证据。

### 手递给另一只

`InteractionRoom.Input.cs` 的 `ProcessHeldSupply` 在换目标前结束旧手势，且接受过一口后由 `_supplyBiteTaken` 阻止同一次拿取连续新建递食。模拟侧也有 `g.Applied` 的一次性入口和 `OfferedSupply` 的剩余份数/手持/种类检查。

所以：A 的尚未入口预留被拿起打断后，这份可以真实递给 B；A 已入口后拿起容器，则只能递剩余份数给 B。旧手势结束不会撤销 A 已入口的收益或再次把它退进容器。这里未发现两条路径叠加成同一份双重入口的具体条件。

### 来源记忆与过期目标

`ObserveNaturalResources` 按每只油自己的观察更新份数是否可用；预留掉最后一份后，它对别人确实已经不可用。取消预留恢复份数后，需要再次实际观察才重新知道有货，这是观察间隔，不是退款丢失。

不可见的物品拿走后，旧位置记忆可能暂时保留；到达可检查的旧位置后才标为不可用。当前寻路只在来源仍可感知时读取其实际位置，目标不可选后会清理当前搜索进度。对确实走不过去的旧位置，原有卡住期限会触发换目标。本轮没有找到默认入口会使过期目标永久阻塞其余生活行为的新增路径。

资源占用与实体阻挡也要区分：其他油站在来源旁造成身体确实无法靠近时，暂时回避是现有绕不开处理，不能仅凭“有人正在吃”就断言为共享预留死锁。

1. **仅一份，A 未入口时被拿起，随后递给 B**：A 暴露和入口收益为零；预留只退一次；B 最终只入口一次；重复取消不增加份数。
2. **两份，A 已入口未咽完时被拿起，再递给 B**：A 的一口保留，B 只消耗第二份；两只各登记自己的实际来源暴露，没有第三份；收起空容器不返还已经吃掉的食物。
3. **拿起又取消，等待者重新接近**：观察 A/B 的个人资源记忆、实际份数、来源 ID 和 pending 状态，区分观察间隔、来源被占用及实体阻挡；最终记录真实剩余份数、已入口次数和未入口预留数。
